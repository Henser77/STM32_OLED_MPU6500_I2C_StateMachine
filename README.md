# STM32 + MPU6500 + OLED：非阻塞软件 I2C 与姿态解算

基于 **STM32F103C8T6** 的一个小项目，核心不是"点亮 OLED"，而是**把 I2C 做成状态机**：
用 TIM2 每 3 µs 打一拍，驱动一条**完全非阻塞**的软件 I2C 总线，OLED（SSD1306）与六轴
（MPU6500）都挂在这条总线上，所有读写都靠**回调**串起来，主循环从头到尾不等待。

```
        ┌──────────── PB6 (SCL) ─────────────┐
STM32 ──┤                                    ├── MPU6500 (0x68)
        └──────────── PB7 (SDA) ─────────────┘
                          │
                          └── SSD1306 OLED (0x3C)
```

## 特性

| 能力 | 说明 |
|---|---|
| **非阻塞软件 I2C** | TIM2 3 µs tick 驱动状态机；`My_I2C_MemRead(addr, reg, buf, len, callback)` 调用后立即返回，完成时回调 |
| 4 种传输原语 | 纯写 / 纯读 / 寄存器写 / 寄存器读，覆盖 OLED（纯写）与 MPU6500（寄存器读写）两类器件 |
| OLED 异步刷屏 | 1024 字节显存缓冲（128×64），`OLED_UpdateScreen(buf, callback)` 后台刷，刷完才回调 |
| MPU6500 异步读取 | 一次突发读 14 字节（加速度 + 温度 + 角速度） |
| **姿态解算** | `atan2` 取加速度倾角 + **一阶互补滤波（α = 0.98）**，陀螺积分提供动态响应 |
| 协作式调度 | `TryNextTransfer()` 轮转"刷屏 / 读数"，两者都靠回调推进，互不阻塞 |
| 按键交互 | 短按循环切三页（加速度 mg / 角速度 0.1°/s / 姿态角 °），长按清零 yaw |
| 时基分离 | SysTick 1 ms 做任务节拍，TIM2 3 µs 做 I2C 位时序 —— 两套时基互不干扰 |

## 为什么这么写

**① 软件 I2C 也可以不阻塞**
常见的 `Delay_us()` 位翻转写法会把 CPU 咬死在一个字节上（128×64 全屏要几十毫秒），
期间按键、串口全丢。这里把 I2C 拆成"每个 tick 推进一小步"的状态机：
起始位 → 地址 → ACK → 数据 × N → 停止位，每一步只占几个微秒。

**② 回调链把"等待"变成"事件"**
`OLED_Init(onComplete)` → 完成后调 `MPU6500_Init(MPU_Ready)` → `MPU_Ready` 里调
`TryNextTransfer()` 进入调度 → 读 MPU 完成 → `MPU_DataReady()` 算姿态 → 回到调度。
整条链没有一个 `while(等待)`。

**③ 互补滤波为什么是 0.98**
加速度计静态准但抖，陀螺积分平滑但会漂。一阶互补滤波 `θ = α(θ + ω·dt) + (1-α)·θ_acc`
用高系数信任陀螺的短时精度、用低系数拉回加速度的长期基准。`dt` 由 SysTick 差值给出。

## 硬件

| 项 | 型号 / 说明 |
|---|---|
| MCU | STM32F103C8T6（72 MHz，8 MHz 晶振 × 9 倍频）|
| 六轴 | MPU6500，I2C 地址 `0x68`，量程 ±2 g / ±250 °/s |
| 显示 | SSD1306 128×64 OLED，I2C 地址 `0x3C` |
| 引脚 | `PB6 = SCL`、`PB7 = SDA`（两器件共用一条总线）|
| 按键 | 短按切页，长按清零 yaw |
| 定时器 | TIM2 周期 3 µs（I2C 位时序）；SysTick 1 ms（任务节拍）|

## 如何编译

1. 安装 **Keil MDK 5** + `Keil.STM32F1xx_DFP` 器件包
2. 打开 `Project.uvprojx`
3. 选择 `Target 1`，`F7` 编译，`F8` 下载（ST-Link / J-Link）
4. 工程已包含 `Library/`（标准外设库）与 `Start/`（CMSIS），**无需额外配置**

> 无实物时也可以在 Keil 的软件仿真里跑（但 I2C 时序要靠真实器件验证）。

## 已知限制（诚实说明）

- **yaw 会漂移**：只有陀螺积分，没有磁力计做绝对航向参考 —— 这是 6 轴 IMU 的固有限制，所以加了"长按清零"
- 软件 I2C 速率约 100 kHz 量级（受 3 µs tick 限制），比硬件 I2C 慢，但换来了任意引脚可用
- 没有做 I2C 总线仲裁/多主支持（单主场景够用）
- 按键消抖用的是"扫描计数"，不是中断 + 定时器方案

## 可以继续做的方向

- 加磁力计（如 AK8963 / QMC5883）做 9 轴融合，解决 yaw 漂移
- 把互补滤波换成 **Mahony / Madgwick**，对比姿态收敛速度
- I2C 状态机加**超时与重试**（当前假设从设备一定应答）
- OLED 换成**局部刷新**（只刷变化区域），进一步降低总线占用
